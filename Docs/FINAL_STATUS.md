## 4. 네트워크 상태

**서버 권한 구조. 실측으로 확인했다.**

클라이언트 → `KitchenNetwork.Request*()` → `[Rpc(SendTo.Server)]` → 서버가 처리
→ `NetworkVariable` 로 전파.

| 서버만 결정 | 주문 생성·완료·만료, 손님, 치킨 상태, 튀김기, 매출, 평판, DAY, 업그레이드, 랜덤 이벤트, 사고, 승패 |
| --- | --- |
| 클라이언트가 하는 일 | 입력 전송, 화면 그리기, 자기 아바타 이동 (NetworkTransform Owner) |

- 클라이언트가 매출·DAY·평판을 직접 바꾸는 경로 **없음** (검증됨)
- `RestaurantGame.Update()` 는 호스트가 아니면 즉시 반환
- RPC 라우팅은 `NetworkManager.ConnectedClients[clientId].PlayerObject` 를 쓴다 —
  등록부 순서에 의존하지 않으므로 남의 조작이 내 캐릭터로 가지 않는다
- 동시 접근: 서버가 한 줄로 처리하고 `Station.Clear()` 가 즉시 자리를 비운다.
  **코드상 안전하나 두 클라이언트 동시 요청은 실측하지 못했다 — UNKNOWN**

기본 포트 7777, LAN 기준. 릴레이 없음.

## 6. 밸런스 상태 — 판정 불가

자동 측정으로는 답이 나오지 않는다. **정직하게 UNKNOWN 이다.**

밸런스 하네스의 봇은 협동하지 못한다. 모두 같은 튀김기로 몰리고, 좁은 주방에서
서로 몸으로 막고, 한 번에 한 마리만 만들며 튀김이 끝날 때까지 서서 기다린다.
그 결과 **봇이 많을수록 더 빨리 망한다** (2 명 DAY 3, 4 명 DAY 4, 1 명 DAY 5~6).
사람이라면 나올 수 없는 결과이므로 이 수치로 난이도를 조정하지 않았다.

측정이 뒷받침하는 것:

| 질문 | 답 |
| --- | --- |
| 초반이 너무 느린가 | **아니다** — DAY 1 에 ₩130k~₩320k |
| 돈을 너무 쉽게 버는가 | **아니다** — 어떤 표본도 목표의 절반을 못 넘었다 |
| 사고가 너무 잦은가 | **아니다** — 표본에서 사고는 거의 없었다 |

나머지는 전부 **UNKNOWN**: DAY 상승 속도, 1,000 만 원 달성 가능성,
업그레이드 균형, 메뉴 최적해, 배달 강도, 사고 확률 적정선.

**사람 2~4 인이 직접 해봐야 답이 나온다.**

## 7. 알려진 버그 / 제약

| 항목 | 내용 |
| --- | --- |
| 손님 경로 | NavMesh 를 쓰지 않고 문에서 줄까지 **직선으로 걷는다.** 가구를 길 밖에 두어 눈에 띄지 않게 했을 뿐이다 |

| 주문 동기화 | 4096 바이트 문자열로 보낸다. 주문이 아주 많을 때의 한계는 **UNKNOWN** |
| 일시정지 | 각자 로컬 화면이다 |
| 릴레이 없음 | 같은 네트워크(LAN)에서만 접속된다 |
| 봇 | 밸런스 판정 근거로 쓸 수 없다 (6 절) |

### 이번 작업에서 잡은 결함 (전부 수정됨)

1. Unity 6 내장 폰트 이름 변경으로 인한 `ArgumentException`
2. 소품·캐릭터가 부모 배율만큼 작아지던 크기 계산 오류
3. 회전한 장식이 절반 크기로 나오던 오류
4. 손님 색 변경의 매 프레임 할당
5. **접속한 플레이어가 불을 끌 수 없었다** (RPC 부재)
6. **기름을 아무도 청소할 수 없었다**
7. 방금 닦은 기름에 미끄러지던 문제 (`Destroy` 지연)
8. **남의 손·튀김기의 치킨을 주워 갈 수 있었다**
9. 저장할 때마다 최고 기록이 지워지던 문제
10. **"미끄럼방지 신발" 이 미끄러짐을 막지 않았다**
11. **기름이 플레이어 행동과 무관하게 무조건 생겼다**
12. **떨어뜨림 → 기름 연쇄가 끊겨 있었다**
13. **남의 캐릭터에 몸이 없어 서로 통과했다**
14. **꺼둔 로컬 캐릭터가 등록부에 남아 사고 판정 대상이 되었다**
15. **치킨이 생길 때마다 NullReferenceException 이 터졌다** (에셋 팩 스크립트)

## 9. 출시 전 남은 작업

우선순위 순.

1. **사람 2~4 인 플레이테스트.** 밸런스는 이것 없이 답이 안 나온다 (6 절)
2. **LAN 실측.** 다른 PC 에서 접속, 재접속, 호스트 종료, 지연
3. **소화기·청소를 클라이언트에서 실제로 해보기.** 코드는 있으나 실측 없음

5. 손님 경로 — NavMesh 도입 여부 판단 (`com.unity.ai.navigation` 필요)
6. 성능 측정
7. 승리 화면이 클라이언트에 어떻게 보이는지 확인

## 10. 실행 방법

```
ChickenGame.exe                          # 타이틀에서 선택
ChickenGame.exe -mode local              # 혼자 바로 시작
ChickenGame.exe -mode host               # 호스트로 열기
ChickenGame.exe -mode client -address 192.168.0.5
```

검증용 인자:

```
-selftest         자동 검증 61 항목
-nettest          접속한 쪽 전용 검증 10 항목
-balancetest N    N 일 자동 플레이
-bots N           측정용 봇 수 (1~4)
-daylength 120    하루 길이
-startday 5       특정 DAY 부터
-startrevenue N   특정 매출부터 (승리 경로 검증용)
-verbose          스폰·네트워크·소품 배치 로그
```
